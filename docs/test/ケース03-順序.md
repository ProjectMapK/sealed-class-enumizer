# ケース03-順序

本資料は K5（中間 sealed）・K7（配置）× O3（entries 順序）の正典である。  
FQN UTF-16 序数と DFS 入れ子展開に関する順序観測は本資料へ集約し、他資料は本資料への参照で足りる（テスト戦略 §3 C4）。  
バイト決定性・IC 編集（改名・移設・追加削除・基底不在ラウンド・宣言順・ロケール）はケース06、跨 module / MPP の順序保存はケース05 が正典を持つ。

## 1. 規則の典拠

- 順序の位置づけ: 仕様としての厳密定義ではなく**破壊的変更の検知**である（網羅性は順序に依存しない）。  
  本資料の期待列は現行コンパイラ挙動の固定であり、変化はスナップショットと決定性テスト（ケース06）の失敗として検知する。
- 順序 = コンパイラの sealed 継承者リスト走査順（setSealedClassInheritors セッター側で ClassId FQN 文字列の UTF-16 序数昇順に正規化・大小区別・ロケール非依存）。
- プラグインは FIR / IR とも並べ替えに一切介入しない（設計00 §6.2・設計02 §3）。
- 中間 sealed はその位置で継承者リストを深さ優先に入れ子展開し、entries には末端のみが載る。
- 整列キーは末端の ClassId のみ（kind が companion でも companion 名は整列に関与しない）。

### 2.2 order.mid（MidRoot・DFS 展開・11 末端）

- 直接末端: data object Aaa / Zzz（トップレベル・展開位置の前後）
- MidNest（トップレベル中間）: ネスト末端 NestA / NestB（局所 FQN 順一致）
- MidTop（トップレベル中間）: トップレベル末端 Early / Late（break）
- MidMulti（トップレベル中間）→ ネスト中間 Deep → ネスト末端 Bottom + トップレベル末端 Wide（多段・深部 break）
- MidRoot.MidIn（基底ネスト中間）: トップレベル末端 Outpost（中間配置=基底ネスト値）
- Probe（class 末端・自動 companion）+ その内側ネスト data object 末端 Bb（inheritors 分岐プローブ）

直接継承者の整列 =
`[Aaa, MidMulti, MidNest, MidRoot.MidIn, MidTop, Probe, Probe.Bb, Zzz]`
（"Mid" 後の 'M'(77) < 'N'(78) < 'R'(82) < 'T'(84)・接頭辞 Probe が Probe.Bb に先行）。  
DFS 展開の期待 entries（label 列）:  
`[Aaa, Bottom, Wide, NestA, NestB, Outpost, Early, Late, Probe, Bb, Zzz]`  
全末端 FQN 一括整列との対比 =
`[Aaa, Early, Late, Bottom, NestA, NestB, Outpost, Probe, Bb, Wide, Zzz]`（MidTop 配下と Wide が break を示す）。  
kind ClassId 整列（inheritors 順）では `Probe.Bb`('B'=66) が `Probe.Companion`('C'=67) に先行し、
entries（末端 ClassId 由来: Probe が Bb に先行）と相対順が分岐する。
