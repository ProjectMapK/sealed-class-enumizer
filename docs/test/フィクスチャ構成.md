# フィクスチャ構成

本書はテストフィクスチャの合成設計（どの次元値をどの階層に同居させるか）と、
テストクラスへの対応の索引である。
合成の許容条件はテスト戦略 §3 C3（実装上相互作用しない次元値のみ同居可・label 一意・
意図しないサブタイプ関係を作らない）に従う。

## 4. TestKit 運用方針

- プラグイン注入は local-repo 経路（前段で `publishAllToMavenLocal`・非タイムスタンプ SNAPSHOT の上書き公開で
  Gradle がキャッシュせず再公開が必ず反映される）。composite 参照は並行実行時に親ビルドが競合するため不採用。
- repositories を宣言するフィクスチャには `mavenLocal()` の併置が必要
  （PREFER_PROJECT で settings 側の dependencyResolutionManagement が無視されるため）。
- 検証手段は 4 種: 診断行位置照合（DiagAsserts）・実行時 OUT 行・生成物 SHA-256（決定性・clean 一致）・
  再コンパイル追跡（classTimes 差分=共連れ/dirty 観測）。
- 診断系は DiagTestBase（PER_CLASS）が 1 フィクスチャ=1 ビルドを実行しクラス内で共有・IC 系は毎回展開する。
- `forwardOutput()` は使わない（並行実行時に結果ストリームが壊れる）。
- 並行実行はテストクラス単位・maxParallelForks=コア数/3・上限 8。
- フィクスチャ展開先は実行前に回収する（蓄積でビルド時間が悪化する）。削除は best-effort。
- native はホスト依存ゲート（Windows=mingwX64）。

## 5. フィクスチャ設計の制約

- 同一階層に合成する末端は単純名一意（意図しない LABEL_CLASH を作らない）。
- 吸収サブタイプは対象末端 1 つのみのサブタイプとする（意図しない AMBIGUOUS_KIND を作らない）。
- diag-fail に置く宣言は互いに独立（1 宣言 1 診断）。同一宣言で他検査を抑止する診断
  （NOT_SEALED の早期リターン等）は共存境界ケースを除き分離する。
- 診断フィクスチャの行位置はアサートの一部であり、編集時は行番号照合を更新する。
  TestKit フィクスチャは ktfmt 整形対象外。
- 順序フィクスチャの期待値は FQN の UTF-16 序数から機械的に導出し、期待列をコメントで併記する。
- producer-jvm のフィクスチャで「1 ファイル 1 クラス」規約より配置制約（同一ファイル要求・
  複数トップレベル宣言）が優先される場合は、ファイル先頭コメントで適用外を明示する。
