# テスト戦略

本書は sealed-class-enumizer の結合テスト体系の正典である。
テストケースは Kotlin 言語仕様の次元モデル（§2）と網羅基準（§3）から導出し、
各ケースの内容と実装対応は分割された各ケース資料（§6）が持つ。
仕様の正は設計資料（概要.md・設計00〜02・エッジケースへの対応方針.md）が持ち、
実装と資料が食い違う場合は実装を正とする。

## 1. 検証対象と非対象

- 検証対象は CLI / Gradle ビルドの成否・診断・生成物・実行時挙動に限る。
  IDE(K2) はサードパーティ FIR プラグインを既定でロードしない（KTIJ-29248）ため、
  IDE / Analysis API 側は検証対象外とする（既定の IDE 体験は概要 §6・設計00 §11 が既知の制限として持つ）。
- 環境: Kotlin 2.4.20-Beta1 / Gradle 9.6.1 / JVM toolchain 17 / `group=io.github.projectmapk`。
- 比較規約: 値の比較はなるべく観測用 data class を組み立て 1 回の `assertEquals` で行う。
  kind の同一性は参照比較（`===`）で行う。

## 3. 網羅基準

- C1（単独網羅）: 各次元の全値を少なくとも 1 ケースが踏む。
  言語上構成不能な値は「構成不能である」ことを固定するケース（言語エラー確認または NG コメント固定）を置く。
- C2（分岐網羅）: 実装に条件分岐が存在する次元の組は全分岐を踏む。
  分岐の典拠は実装である: kind 解決（object=自身/他=companion）・asEnumish 返り値型 3 段規則・
  IR-only アクセサの壁 3 形（壁なし/ネスト壁/トップレベル壁）・toString 生成の 3 非生成条件・
  companion 自動生成の候補判定（raw supertype 追跡のスコープ順 5 表記）・順序（DFS 入れ子展開×FQN 正規化）。
- C3（合成許容）: 実装上相互作用しない次元値は同一フィクスチャに合成してよい。
  根拠は生成が末端毎に独立（P1）・診断が宣言単位の条件検査であること。
  合成時の制約: 同一階層内の label 一意・意図しないサブタイプ関係を作らない・
  診断フィクスチャでは他検査を抑止する診断（NOT_SEALED 等）を独立宣言に分離する。
- C4（正典配置）: 順序=ケース03、診断=ケース04、IC・決定性=ケース06 を正典とし、
  他資料の重複する観測は正典への参照で足りるものとする。

## 4. テストモジュール構成

integration-test は親ビルドを composite 参照する独立 Gradle ビルドであり、8 モジュールから成る。
「コンパイル成功で証明できる正値」は通常モジュール、「コンパイル失敗・2 回ビルド差分・バイト一致・別版組合せ」は
TestKit（gradle-integration）に置く。

| モジュール | プラグイン | 役割 |
|---|---|---|
| producer-jvm | 適用 | 生成側。合成フィクスチャ群と同一 module 限定の box（ケース01〜03 の正典） |
| consumer-pure-jvm | 未適用 | 純消費。生成 API のメタデータ参照・跨 module 網羅 when(V1-a)・E-2 外部観測面 |
| consumer-plugin-jvm | 適用 | 適用消費の正値基線。両側適用 when・自前階層との共存 |
| downstream-subtype-jvm | 未適用 | 非 final 末端(V10)の下流サブタイプ吸収 box |
| java-consumer | 未適用(Java 21) | Companion フィールド経由アクセス・JEP 441 switch・失敗文言の Java 観測 |
| mpp-producer | 適用 | MPP 生成側。common フィクスチャ+全 5 ターゲット box・klib/metadata(V5) |
| mpp-consumer | 未適用 | MPP 純消費。common からの生成 API 参照・跨 module×MPP の when |
| gradle-integration | TestKit | 診断（負値・near-miss）・IC 回帰・決定性・ABI 伝播・旧バイナリ・基底不在ラウンド |

## 5. 状態と ID 規約

- 状態: `実装済` / `保留`（駆動機構がなく検証不能。保留.md が管理） / `既知の制限ゲート`（実挙動を固定する回帰ゲート+仕様側 @Disabled）。
- ID: `<資料略号>-NN`（API / VIS / ORD / DIA / XMP / BLD）。保留は `PEN-NN`・既知の制限は `GATE-NN`。
  採番は追加順であり節の並びと一致しない場合がある。欠番は繰り上げない。
- 1 ケース = 言語仕様空間の 1 つの論理的観測。1 テストメソッドが複数ケースを担ってよく、
  対応は各ケース表の実装列が持つ。
