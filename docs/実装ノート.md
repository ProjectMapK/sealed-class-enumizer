# 実装ノート（プロダクションコード v1）

本書は設計資料（[設計00](コンパイラプラグイン設計00.md)・[設計01](コンパイラプラグイン設計01.md)・
[設計02](コンパイラプラグイン設計02.md)・[エッジケースへの対応方針](エッジケースへの対応方針.md)）を
プロダクションコードへ落とした際に確定した、**設計資料に書かれていない実装固有の事項**を記録する。
仕様の正は各設計資料が持ち、V 項目の検証状況は設計00 §10（未検証範囲）が持つ。
実測環境: Kotlin 2.4.20-Beta1（K2 / JVM）・Gradle 9.5.0。

## 1. モジュール構成と検証状態

- `runtime-api`（MPP: jvm / js / wasmJs / wasmWasi / linuxX64 / mingwX64 / macosX64 / macosArm64）・
  `compiler-plugin`・`gradle-plugin`（plugin id `org.wrongwrong.sealed-class-enumizer`）を実装済み。
  パッケージルートは `org.wrongwrong.sealedClassEnumizer`（group=org.wrongwrong に統一）。
- `integration-test` は[テストケース管理](テストケース管理.md)の計画どおり独立 composite build として、
  **8 モジュールすべてを実装済み**である。
  - `producer-jvm`: 同一モジュール box 160 テスト。フィクスチャは、実装が複数ファイルにまたがる・
    または独立階層を要するケースをケース毎のサブパッケージ（約 30 個）へ分けて区別し、
    単一ファイルで完結するケースは `org.wrongwrong.fixtures` 直下に置く。
    sealed の同一パッケージ制約はケース単位の移動で保たれ、階層内の FQN 相対順序も変わらない。
  - `consumer-pure-jvm`（未適用・33）/ `consumer-plugin-jvm`（適用・7）/ `downstream-subtype-jvm`（6）/
    `java-consumer`（Java 21・7）: 跨モジュール参照・else 無し kind-when（V1-a・短縮形含む）・
    E-2 外部観測・非 final 末端の下流吸収・Java 相互運用（Companion フィールド経由・網羅 switch）。
  - `mpp-producer` / `mpp-consumer`: jvm / js / wasmJs / wasmWasi / mingwX64（ホスト依存）の全ターゲット
    box と metadata（V5）・中間ソースセット（webMain）・跨モジュール共通コード参照。
  - `gradle-integration`: TestKit。診断カタログ（Diag* 9 クラス + フィクスチャ diag-*）と
    IC 回帰 / 決定性 / ABI 伝播 / 旧バイナリ差し替え / KT-86121 ゲート（Ic* / Determinism* /
    AbiPropagation* / BinarySwap* / Kt86121*）。フィクスチャはプレースホルダ置換で親ビルドを
    composite 参照する（TestKitHarness）。
- 未適用モジュールの暫定的な runtime-api 明示宣言は、gradle-plugin が runtime-api を api で自動公開する
  （概要 §7）ため、プロジェクト参照の消費側からは除去した（推移メタデータを持たない依存形態など
  別要因で要する一部は存置）。
- 実装で発見された仕様と実挙動の乖離（11 項目）は[修正方針案](修正方針案.md)に集約した。
  該当テストは仕様どおりのアサートのまま `@Ignore` / `@Disabled` で保持している。

## 2. 実装固有の事項（設計資料に無い実装詳細）

設計01・設計02 が方式を定めた上で、実装時にのみ現れた低レベルの事項を記録する。

1. **生成 Enumish の companion 連結における `ownerGenerator` の刻印**（設計01 §5.1 が参照）。
   生成した companion を `replaceCompanionObjectSymbol` で自前連結する際、
   `FirGeneratedScopes.getExtensionsForClass` が要求する内部属性 `ownerGenerator` は provider 経由でしか
   刻印されない。`EnumizeOwnerGeneratorPatch` がリフレクションで刻印する
   （Kotlin のマイナーバージョン毎のアーティファクト分割 — 概要 §7 — の下でバージョンに固定される）。
2. **生成プロパティの backing field の除去**。FIR の生成宣言が default アクセサ形
   （`FirDefaultPropertyGetter`）のため、Fir2Ir が backing field を実体化することがあり、
   interface 上ではインスタンスフィールドとなって不正な class file（`ClassFormatError`）になる。
   IR のボディ充填時に `backingField = null` で除去する。
3. **`CompilerPluginRegistrar.pluginId`** は 2.4 系で必須の abstract プロパティである（設計資料には未記載）。
4. **`ENUMIZE_MANUAL_IMPL_OUTSIDE_HIERARCHY` の対象認識は origin だけに依らない**。
   `FirDeclarationOrigin.Plugin` は IC ラウンド外のファイル由来（前ラウンドのメタデータからの逆直列化）では
   失われる。階層メンバーは階層不変条件により基底が常に共連れされるため origin 判定で足りるが、階層外の
   手動実装だけはラウンドを跨ぐため、対象認識は「@Enumize 付き基底の直下の `Enumish`」という構造判定で行う。
   `@Enumize` の判定も述語（ソース宣言限定）に加えて、アノテーションの直接照合（Retention が BINARY のため
   メタデータに残る）で補う。IC ラウンド（基底ファイルがラウンド外）でも発火することを確認済み。

## 3. 敵対的検証（診断テスト）で発見・修正した欠陥

K2 コンパイラを直接起動する一時的な診断テスト（発火 23 件・非発火 17 件、ケースはテストケース管理
G 軸の TC-DIAG に対応）で検証を行い、次の欠陥を修正した。修正は compiler-plugin 本体に反映済みであり、
検証に用いたテスト一式はその後撤去した（診断の常設テストは gradle-integration の TestKit diag テストとして
実装済み。G 軸の実装状況は[テストケース管理](テストケース管理.md)の状態列が持つ）。

1. **間接継承経由の `Enumized<別型>` が未検出**（エッジ §2「判定は間接継承も対象とする」との差分）。
   基底の supertype 閉包に対する検査と、注入スキップ判定の推移化で修正（TC-DIAG-051）。
2. **階層外クラスの companion が単独で末端になる許容構成が不成立**（設計01 §7.2
   COMPANION_LEAF_CONFLICT の注記との差分）。companion への supertype 注入もメンバー生成も行われず
   ABSTRACT_MEMBER_NOT_IMPLEMENTED になっていた。companion 自身の末端判定を外側基準の kind 判定より
   先に行う分岐で修正（TC-DIAG-037）。
3. **typealias 経由の supertype で「明示的な companion は常に完全なワークアラウンド」（設計01 §6.2）が
   破綻**。解決済み ref の ClassId がエイリアスのままで階層判定・注入・メンバー生成がすべて素通りしていた。
   解決済み型の `fullyExpandedType` 展開と、raw 段階での typealias 追跡（`followTypeAliases` フラグ）で修正。
   companion 自動生成の候補判定だけは設計どおり typealias を辿らず、`ENUMIZE_COMPANION_REQUIRED` で
   明示宣言を促す契約を維持する（発火 TC-DIAG-057/058・非発火 TC-DIAG-060 の両面で検証）。

このほか `ENUMIZE_ON_EXPECT` は `-Xmulti-platform` 下で発火し、expect 宣言への生成も ICE を
起こさないことを確認した（`ENUMIZE_ON_ACTUAL` / `ENUMIZE_CROSS_SOURCE_SET` を含む常設の診断検証は
gradle-integration の TestKit diag テストへ移行済み。`ENUMIZE_CROSS_SOURCE_SET` は発火しないことが
判明している — [修正方針案](修正方針案.md) #9）。
