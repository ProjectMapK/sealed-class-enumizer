本書は設計資料（[設計00](コンパイラプラグイン設計00.md)・[設計01](コンパイラプラグイン設計01.md)・[設計02](コンパイラプラグイン設計02.md)・[エッジケースへの対応方針](エッジケースへの対応方針.md)）
に載らない、プロダクションコード固有の実装事項の索引である。  
各事項の詳細と根拠は実装箇所のコメントを正とし、本書は所在と要点のみを示す。  
本書は他資料への**補足**であり、参照は常に本書から他資料へ向かう（ソースコードおよび設計資料・概要・
テスト資料から本書を参照しない。それらが要する内容は各資料自身が持つ）。  
実測環境: Kotlin 2.4.10（K2 / JVM）。

## 1. テストの分担

- `compiler-plugin` / `gradle-plugin` / `maven-plugin` の単体テストは定数と登録の一致検証や
  期待値固定に限り、生成挙動とビルドツール上の適用の検証は独立 composite build の
  `integration-test`（[テスト戦略](test/テスト戦略.md) §4）が持つ。
- 仕様と実挙動の乖離は[修正方針案](修正方針案.md)が持つ。  
  該当テストは仕様どおりのアサートのまま `@Ignore` / `@Disabled` とする。

## 2. 実装固有の事項（設計資料に無いもの）

1. **生成 companion への `ownerGenerator` の刻印**（`EnumizeOwnerGeneratorPatch`）。  
   `replaceCompanionObjectSymbol` による自前連結（設計01 §5.1）では内部属性が未設定のままになるため、
   リフレクションで刻印する（Kotlin のマイナーバージョン毎のアーティファクト分割の下でバージョンに固定される）。
2. **生成プロパティの backing field の除去**（`EnumizeIrContext`）。  
   Fir2Ir が実体化する backing field が interface 上で不正な class file になるため、ボディ充填時に除去する。
3. **`ENUMIZE_MANUAL_IMPL_OUTSIDE_HIERARCHY` の対象認識は origin 非依存の構造判定**
   （`EnumizeHierarchyResolver.representsGeneratedEnumish`）。  
   IC ラウンド外のファイル由来（前ラウンドのメタデータからの逆直列化）では origin が失われるため。  
   `@Enumize` の判定も述語に加えてアノテーションの直接照合で補う（`EnumizeRawSupertypeTracker`）。
4. **プラグイン本体は runtime-api をロードせず、名前定数はリテラルで持つ**（`EnumizeNames`）。  
   公式・著名プラグインと同じ構成である。  
   宣言をロードして名前を導出する構成は、Kotlin/Native のコンパイラプラグインクラスパスが推移依存を解決しない（実測）
   ため plugin jar への同梱が必須になり、relocation で ClassId が静かにずれる経路を抱える。  
   リテラルと runtime-api 宣言の一致は `EnumizeNamesTest` が担保する（改名すると失敗して更新漏れを検知できる）。

## 3. 保留

駆動機構が無く検証不能な領域と既知の制限ゲートは[保留](test/保留.md)が持つ。
